# Connect your AI tools

DesignOS's MCP server uses stdio and opens the active library read-only. It never migrates, cleans staging, or edits saved references. SQLite may create empty journal/shared-memory sidefiles on the first read of a closed library; database content and reference files remain unchanged. Each request resolves the active library again, so switching libraries in DesignOS does not require a new AI session. An explicit `--library` argument intentionally pins one library instead. The `DESIGNOS_LIBRARY` environment variable also pins a library; legacy `MAGPIE_LIBRARY` remains supported. `--library` takes precedence over both variables.

Open DesignOS → Settings → AI tools, choose **Claude Code**, **Codex** or **Other clients**, and copy the setup command or configuration. Run a command once in Terminal, or paste the JSON into a compatible client's MCP settings. Restart the AI tool, then ask: “Find references for a pricing page in my DesignOS library.” If setup fails to load, choose **Retry setup**; local text recognition and visual-search settings remain available.

Generated values point to the running packaged executable and its bundled `out/main/mcp.js`, with `ELECTRON_RUN_AS_NODE=1` and the app's user-data directory. Using these values avoids assuming a global Node runtime or a particular install location. Install DesignOS in Applications before connecting; a configuration pointing to a temporary build or renamed app stops working if that app moves.

The Claude Code command uses `--scope user`, so setup works across your projects rather than only in Terminal's current folder. Codex also saves its command-based setup in your user configuration. JSON setup follows the scope of the client settings file you choose.

## What your AI tool can read

Only visible references in the open library are shared. Hidden and trashed references are excluded from search, direct reads and tag counts. MCP never edits saved references or library metadata. References sent to an AI client are handled under that client's data policy; read-only access does not mean those references stay on-device.

| Tool | Result |
| --- | --- |
| `search_references` | Up to 12 matching references, descriptions and WebP thumbnails. Tags, collection IDs, colors, sources and dates can narrow results. |
| `get_reference` | Full metadata and a WebP image up to 1568 pixels. For carousels, pass the zero-based `slide` index; videos return still posters. |
| `list_collections` | Nested collections, visible counts and unambiguous `in:<collection UUID>` filters. |
| `list_tags` | Tags and counts from visible references. |

If the optional local model is missing or damaged, search falls back to text and filters with a notice. A missing or damaged preview falls back to its other local image; if neither can be decoded, metadata remains available with an explanation. The server does not download models during a query.

## JSON configuration

The same JSON can be reviewed as a workspace `.mcp.json` before enabling it. It has this shape; replace the placeholders with the values generated by DesignOS:

```json
{
  "mcpServers": {
    "designos": {
      "command": "<DesignOS executable>",
      "args": ["<app.asar>/out/main/mcp.js", "--user-data", "<DesignOS user-data directory>"],
      "env": { "ELECTRON_RUN_AS_NODE": "1" }
    }
  }
}
```

`claude mcp get designos` checks whether the configuration exists. `claude mcp list` checks configured server health without starting a Claude conversation. A successful connection proves transport/server availability; it does not by itself prove that an AI conversation received and interpreted image content.

## Upgrading from Magpie

Existing MCP entries contain absolute paths to the old app. After installing DesignOS, copy the updated configuration from **Settings → AI tools**, replace the old entry in your assistant, and restart its MCP connection. Your library and pairing remain in the existing profile; keep the old app until the new connection is verified.
