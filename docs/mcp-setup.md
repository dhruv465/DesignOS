# Claude Code MCP connection

DesignOS's MCP server uses stdio and opens the active library read-only. It never migrates, cleans staging, or writes the library. Each request resolves the active library again, so switching libraries in DesignOS does not require a new AI session. An explicit `--library` argument intentionally pins one library instead. The `DESIGNOS_LIBRARY` environment variable also pins a library; legacy `MAGPIE_LIBRARY` remains supported. `--library` takes precedence over both variables.

Open DesignOS → Settings → AI tools and copy the generated Claude Code command or MCP JSON. These values point to the running packaged executable and its bundled `out/main/mcp.js`, with `ELECTRON_RUN_AS_NODE=1` and the app's user-data directory. Using the generated values avoids assuming a global Node runtime or a particular install location.

The same JSON can be reviewed as a workspace `.mcp.json` before enabling it. It has this shape; replace the placeholders with the values generated by DesignOS:

```json
{
  "mcpServers": {
    "designos": {
      "command": "<DesignOS executable>",
      "args": ["<app.asar>/out/main/mcp.js", "--user-data", "<DesignOS user-data directory>"],
      "env": { "ELECTRON_RUN_AS_NODE": "1" }
    }
  }
}
```

`claude mcp get designos` checks whether the configuration exists. `claude mcp list` checks configured server health without starting a Claude conversation. A successful connection proves transport/server availability; it does not by itself prove that an AI conversation received and interpreted image content.

## Upgrading from Magpie

Existing MCP entries contain absolute paths to the old app. After installing DesignOS, copy the updated configuration from **Settings → AI tools**, replace the old entry in your assistant, and restart its MCP connection. Your library and pairing remain in the existing profile; keep the old app until the new connection is verified.
